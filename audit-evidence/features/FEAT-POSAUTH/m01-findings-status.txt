WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-6-
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md:7:1. **FINDING-7A-01 (HIGH) — Animated Reset Layout Race Condition**:
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-8-   - **Issue**: Executing `resetLayout()` when `animate: true` synchronously invoked `captureAndPersistPositions()` at $t=0$ of the animation, capturing pre-animation starting coordinates instead of final layout coordinates.
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-9-   - **Fix**: Centralized reset layout execution in `executeResetLayout` in `GraphView.tsx`. When animation is enabled (`!prefersReducedMotion && nodes.length < 100`), the function registers a `layoutstop` event listener on Cytoscape prior to invoking `runLayout(cy, { animate: true })` and captures/persists coordinates only upon layout animation completion.
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-10-
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md:11:2. **FINDING-7A-02 (MEDIUM) — Session Authority Promotion & Stale Persisted Override**:
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-12-   - **Issue**: Canvas node coordinates (`cyPositionsBefore`) were silently written into `sessionPositionsRef` (Level 1 authority) during element synchronization in `useEffect([nodes, edges])`. Consequently, external updates to `nodePositions` (Level 2 authority) could never override rendered positions while `GraphView` remained mounted.
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-13-   - **Fix**: Removed `sessionPositionsRef` insertion during `cyPositionsBefore` capture. Level 1 session drag authority is now populated strictly by explicit user drag actions (`cy.on('dragfree')`). `cyPositionsBefore` remains strictly Level 3 canvas authority. Added `nodePositions` to the Element Sync `useEffect` dependencies so external prop updates immediately update undragged nodes on canvas.
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-14-
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md:15:3. **FINDING-7A-03 (LOW) — New Node Position Persistence**:
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-16-   - **Issue**: Coordinates assigned to genuinely new nodes via `calculateDeterministicNewNodePosition()` were placed on canvas and stored in `sessionPositionsRef`, but `onNodePositionsChangeRef` was not invoked immediately to persist them to project state / `localStorage`.
WAVE8A_RUNTIME_POSITION_AUTHORITY_IMPLEMENTATION.md-17-   - **Fix**: Tracked `newlyPlaced = true` whenever genuinely new nodes are positioned during mount or element sync. When `newlyPlaced` is true, `captureAndPersistPositions()` is invoked to notify parent state listeners and save coordinates immediately.
