# PHASE 13 — HYBRID LAYOUT REAL-WORLD EXECUTION FORENSIC AUDIT

## 1. Executive Summary

This forensic investigation was commissioned to determine why the actual running application was rendering a Hierarchical Layout instead of the expected Hybrid Layout when loading the canonical benchmark fixture `audit-fixtures/cloud-spend-tracker/explorer-data.json`.

Prior Phase 12 documentation claimed that Hybrid Layout was fully activated and visually verified. However, real runtime analysis of the executable application revealed two critical production wiring flaws that prevented Hybrid Layout from appearing on screen:

1. **Stale Automatic Position Overwrite Bug in `resolveAuthoritativePosition`**:
   When switching `architectureMode` to `'hybrid'`, `hasAuthoritativePositions` evaluated to `false` because stored positions had `layoutProvenance: 'automatic-hierarchical'`. Cytoscape was correctly initialized with fresh Hybrid positions generated by `computeArchitectureLayout`. However, during component mount and element sync loops in `GraphView.tsx`, `resolveAuthoritativePosition(id, { persistedPositions })` was called without passing `hasAuthoritativePositions`. Because `hasAuthoritativePositions` defaulted to `true` inside `position-policy.ts`, Level 2 persisted position authority unconditionally returned the stored Hierarchical positions, forcefully overwriting **all 240 fresh Hybrid positions**!
2. **Public Fixture Mismatch**:
   The default dataset located at `explorer/public/explorer-data.json` contained a dummy 4-node graph instead of the 240-node Cloud Spend Tracker benchmark dataset.

After applying surgical fixes to `position-policy.ts` and `GraphView.tsx` and synchronizing `public/explorer-data.json`, node overwrites dropped from **240 nodes to 0 nodes**. Real UI browser verification using Playwright confirmed that the graph rendered in Hybrid mode visibly displays clustered feature regions (`Cloud_Spend__c`, `Spend_Import_Batch__c`, `User_Organization_Role__c`). Direct renderer coordinate analysis verified Candidate E canonical metrics ($C_{pp} = 8,704, C_{ps} = 41,590, C_{ss} = 41,544, C_{pb} = 2,594, C_{bb} = 230, C_{total} = 94,662$).

## 23. Root Cause

1. **`resolveAuthoritativePosition` Ignored `hasAuthoritativePositions` Option**:
   Inside `position-policy.ts`, `resolveAuthoritativePosition(nodeId, options)` assigned a default parameter `hasAuthoritativePositions = true`. When `GraphView.tsx` called `resolveAuthoritativePosition(nodeId, { persistedPositions })` during initial node population without explicitly passing `hasAuthoritativePositions: hasAuth`, Level 2 persisted position authority triggered unconditionally. This forcefully replaced every fresh Hybrid position with the old stored Hierarchical position.
2. **Public Fixture Mismatch**:
   `explorer/public/explorer-data.json` contained a dummy 4-node dataset instead of the 240-node Cloud Spend Tracker fixture.

---

## 24. Minimal Surgical Fix

1. **`explorer/src/lib/position-policy.ts`**:
   Updated Level 2 position resolution check:
   ```typescript
   if (hasAuthoritativePositions && persistedPositions && persistedPositions[nodeId]) {
     return { position: { x: pos.x, y: pos.y }, level: 2 };
   }
   ```
2. **`explorer/src/components/GraphView.tsx`**:
   Passed `hasAuthoritativePositions: hasAuth` into all `resolveAuthoritativePosition` calls during element initialization and sync loops.
3. **Fixture Files**:
   Updated `explorer/public/explorer-data.json` and `explorer/public/projects/cloud-spend-tracker/explorer-data.json` to match `audit-fixtures/cloud-spend-tracker/explorer-data.json`.
