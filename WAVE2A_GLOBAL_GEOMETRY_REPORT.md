## 1. Root Cause Addressed

This implementation resolves **ROOT CAUSE #1** identified during the forensic spatial distance audit:

> `global-layout.ts` calculated domain region width and grid column count from ALL nodes mapped to a domain, including secondary satellite nodes such as custom fields (`isField`) and unit tests (`isTest`).

### Confirmed Propagation Chain Fixed
```
[Secondary Node Count (Fields + Tests)]
       │
       ▼
[Inflated domain nodeCount in buildDomainGraph]
       │
       ▼
[cols = ceil(sqrt(nodeCount)) capped at 4]
       │
       ▼
[regionWidth = cols * 156 + 40 (pre-allocated up to 664px+)]
       │
       ▼
[currentX += regionWidth + (domainSpacing - 220)]
       │
       ▼
[Compounding global horizontal X expansion across domains]
```

By decoupling global domain region bounds from secondary satellite nodes, global architecture geometry now strictly represents the **PRIMARY architecture** (Apex classes, controllers, services, repositories, selectors, objects).

## 4. Old Geometry Model

In the old model:
- `cols = Math.max(1, Math.min(4, Math.ceil(Math.sqrt(nodeCount))))`
- `rows = Math.max(1, Math.ceil(nodeCount / cols))`
- `regionWidth = Math.max(220, cols * (nodeWidth * 1.3) + 40)` (where `nodeWidth = 120`, resulting in 664px width for 4 columns)
- `regionHeight = Math.max(150, rows * (nodeHeight * 1.4) + 40)`
- `currentX += regionWidth + (domainSpacing - 220)` (fixed +160px center offset addition with default `domainSpacing = 380`)

### Flaws in Old Model
1. A domain with 1 Apex Class and 30 custom fields was assigned 4 grid columns, allocating 664px of global horizontal width.
2. The next domain was placed at `currentX += 664 + 160 = 824px` farther right regardless of actual production node footprint.
3. Domain primary layer was determined by total node count, causing Apex classes in the `domain` layer to be placed at Schema Y coordinates (`850px`) if the domain contained many custom fields.

---

## 5. New Geometry Model

In the new model:
- Primary nodes inside each domain are grouped by architectural layer (`presentation`, `application`, `domain`, `schema`).
- For each layer bucket, primary nodes are arranged into rows capped at 4 columns (`MAX_COLS = 4`).
- `maxCols = Math.max(1, ...layerBuckets.map(bucket => Math.min(4, primaryCountInBucket)))`
- `maxRows = Math.max(1, ...layerBuckets.map(bucket => Math.ceil(primaryCountInBucket / 4)))`
- `primaryWidth = maxCols * nodeWidth + Math.max(0, maxCols - 1) * horizontalGap` (default `horizontalGap = 40`)
- `primaryHeight = maxRows * nodeHeight + Math.max(0, maxRows - 1) * verticalGap` (default `verticalGap = 40`)
- `regionWidth = Math.max(160, primaryWidth + 40)`
- `regionHeight = Math.max(100, primaryHeight + 40)`

### Benefits
1. Domain region geometry scales strictly with the max columns/rows required by primary production nodes in any layer bucket.
2. A domain with 1 primary node and 30 fields allocates a compact 160px region width (`120px node width + 40px padding`).
3. Primary node positions generated by `computeLocalNodeLayout` center within `[xMin, xMax]` and remain strictly contained inside region bounds.

## 6. Primary-vs-Secondary Treatment

- **Primary Architecture Nodes:** Identified using canonical project semantics (`!isTestNode(node) && !isFieldNode(node)`). These include ordinary production Apex classes, controllers, services, repositories, selectors, handlers, flows, and objects.
- **Secondary Nodes:** Identified as unit tests (`isTest = true`) and object custom fields (`isField = true`).
- **Isolation Boundary:** Global domain region sizing, bounds, and inter-domain origins are calculated using primary nodes only. Secondary nodes do NOT influence global domain geometry, origins, or X advancement. Satellites expand locally during Step 10 (`placeSatellites`).

## 7. Domain Gap Model

The fixed advancement `currentX += regionWidth + (domainSpacing - 220)` was replaced with right-edge-to-left-edge gap placement:

$$\text{Next Domain } x_{\text{Min}} = \text{Previous Domain } x_{\text{Max}} + \text{domainGap}$$

### Relationship-Aware Gap Calculation
$$\text{domainGap} = \text{maxGap} - S \times (\text{maxGap} - \text{minGap})$$

Where:
- $\text{minGap} = 80\text{px}$ (hard minimum readable inter-domain clearance)
- $\text{maxGap} = 140\text{px}$ (maximum preferred separation for uncoupled domains)
- $S \in [0.0, 1.0]$ is the normalized cross-domain edge coupling strength between the adjacent domain pair from `domainGraph.adjacency`.

### Properties
1. Strongly coupled adjacent domains ($S = 1.0$) are placed closer together ($80\text{px}$ gap).
2. Uncoupled adjacent domains ($S = 0.0$) maintain clear visual separation ($140\text{px}$ gap).
3. Domains never overlap ($x_{\text{Min}, i+1} \ge x_{\text{Max}, i} + 80\text{px}$).
4. Fully deterministic and independent of input array ordering.

## 10. Determinism Verification

All calculations in `global-layout.ts` maintain strict 100% determinism:
1. Input node and edge arrays are defensively cloned and sorted by ID before graph construction.
2. Domain ordering uses deterministic barycentric sweeps with alphabetical tie-breakers.
3. Floating point coordinate math is pure and deterministic.
4. No reliance on non-deterministic data structures, viewport state, `Math.random()`, or `Date.now()`.

## 12. Remaining Known Spacing Issues

1. **Disconnected Component 1D Horizontal Shift (WAVE 2C):** Disconnected components that overlap horizontally are currently shifted linearly along the X-axis in `architecture-layout.ts` Step 10, stretching multi-component graphs horizontally (e.g. `sparse-graph` and `scale-100-plus`). Integrating 2D shelf component packing (`packComponentPositions`) in Wave 2C will compact these subgraphs into a balanced 2D aspect ratio (~1.6 to 2.0).
2. **Fixed Architectural Layer Y Coordinates (WAVE 2B):** Architectural layers remain fixed at hardcoded Y band base coordinates (`presentation: 100`, `application: 350`, `domain: 600`, `schema: 850`). Dynamic layer Y spacing based on actual primary row counts will be implemented in Wave 2B.
